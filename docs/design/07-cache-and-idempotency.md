# 07 缓存与幂等

状态：已有响应缓存；internal/gateway/spend.go 的 writeCacheHit 会从旧响应抽出 usage 并调用普通 recordSpend，存在把缓存命中按生成 token 再收费的设计问题。跨请求的持久化业务幂等尚未形成统一契约。

## 缓存语义

缓存命中返回的内容可以保持原协议响应，但当前调用计量必须独立：cache_hit=true、generated input/output usage=0、generation_charge=0。原输出 usage 放在 provenance.original_usage，不再进入当前生成计费。若产品收缓存读取费用，用 cache_read 单位、明确价格和独立分录；不得未经声明收取原生成价。

不要将网关响应缓存与供应商 prompt cache 混淆。供应商 prompt cache hit 仍然执行上游，通常有输入缓存 token 和生成输出 token，按供应商及产品政策正常计量；网关 full response hit 才跳过生成。

## 键、隔离与命中条件

规范请求摘要包含 tenant/scope、模型别名及语义版本、操作、规范输入、生成参数、system/tool 定义、协议版本、响应格式、适配器版本及必要部署语义。涉及个性数据默认不跨租户共享。密钥不直接参与缓存键；配置版本用于防止撤销后旧配置继续命中。

命中前仍要认证、授权、检查模型发布及缓存访问策略；缓存不能让被撤销模型继续可用。读取到条目后校验数据版本、完整性和过期时间。错误响应、partial/unknown 流、未完成任务不作为成功结果缓存。流式缓存只有收齐并验证终态才能写入；读取时按协议重新分帧，不能伪造新的上游 TTFT。

TTL 明确控制内容新鲜度，模型更新和撤销触发失效。缓存不可用时可降级到真实调用，但必须重新做限流和预算预占；不得把 cache backend 失败作为零成本调用。

## 业务幂等

幂等作用域为 principal/scope + operation + Idempotency-Key。持久化保存规范请求摘要、execution_id、状态及可重放结果引用。相同键且相同请求返回同一业务结果/任务；相同键但请求不同返回 409 idempotency_conflict；处理中返回约定的进行中响应，而不是重新发送上游。

执行记录创建与请求关联、预占及提交意图在同一事务。唯一约束使并发重复请求只有一个执行者；其他请求各自有事件并标 idempotency_replay，当前请求无重复生成计费，引用原 execution 的结算而不再次累计。

保存期至少覆盖最长任务、客户端重试窗口和供应商幂等有效期；过期策略返回明确提示。清除键后再次提交可能是新工作，不能宣称永久 exactly-once。供应商幂等键使用稳定 execution_id 派生，不能按 attempt 新建；也不能跨不同部署复用后假设供应商能互相去重。

## 故障与边界

本地记录与外部发送不在一笔事务。若进程在发送后持久化结果前退出，有供应商幂等时查询/重放同键恢复；无幂等且无法按请求 ID 查询时标 unknown，禁止自动重发。客户端自行换键会产生新工作，这属于明确的新提交，页面应展示已有未知任务供核查。

Redis 分布式锁仅减少重复竞争，不提供业务正确性；锁过期后第二个 worker 仍可能执行，数据库唯一 execution 状态和外部幂等才是保证。provider 请求幂等、内部结算幂等和响应缓存必须分别测试。

## 迁移与验收

先修缓存计量入口并添加 charge_kind，再引入持久化幂等记录，最后把媒体提交和有副作用操作接入。历史缓存条目如果没有版本/完整终态标记则失效，不迁移为可信新条目。

验收：命中一百次生成费用仍只有原执行一次；不同租户不会交叉命中；权限撤销后不返回缓存；同键并发提交只生成一个 task；同键不同 payload 为 409；重复请求有日志但没有重复收费；崩溃恢复不以换部署方式重做结果未知的工作。参见 [异步协议](09-async-media-and-seedance.md)。
