## 迁移机制

数据库采用扩展后收缩：先加表/可空字段/索引，再回填和校验，应用切到新读写，最后移除旧字段。具体 SQL 和数据库隔离级别在实施时按实际引擎验证。大表回填分批带检查点，避免长事务堵住准入。

新请求事件可与旧 SpendLog 双写比较，比较记录带 origin 与关联 ID；只有一条账务链路真正收费。影子 BillingService 只算结果，不更新余额、不发退款。切换采用范围隔离和数据库内 billing_owner_version/fencing，禁止旧/新 worker 同时拥有同一 execution。版本不匹配拒绝写入。

切换时暂停相应范围新准入，排空或标记进行中工作，从同一一致性水位导入账户期初余额、未结预占和待核查项。旧明细无法证明时建立 origin=legacy 的期初/待对账记录；不要同时导入期初余额并再累加全部旧明细。缺失价格、身份、模型和单位显式 unknown，不以当前数据补造。

影子比较按 request/execution/settlement 键对齐，区别 HTTP 请求计数和生成计数，纳入失败/缓存/重放/异步用量。金额使用同币种和相同舍入规则；所有差异先解释或修复后切换，不能用容差掩盖重复扣款。

## 发布与回滚

各开关按 scope/provider/operation 设置，默认为未验证能力关闭。部署前保留数据库备份、迁移版本、支持矩阵和可用性策略版本。先内部测试账户，再受限实验，最后按证据开放。

触发停止准入的条件：越权、重复收费、硬预算越界、结算事务部分写入、大量 unknown 或不可恢复事件缺失。报表水位过旧可暂停报告切换，不自动重做上游。上线容量与业务 SLA 决定具体告警阈值。

回滚优先关闭新准入、保留 schema 和新账本，由兼容 worker 完成已提交任务/结算。新系统已收费后不可直接回到旧 recordSpend，否则可能重扣。需要反向迁移时先停写、对账、转移唯一写所有权并验证；不得删除已经发生的财务事实或凭据撤销记录。
