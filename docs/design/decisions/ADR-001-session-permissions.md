# ADR-001 会话撤销与统一能力授权

状态：Proposed（待实施）。日期：2026-10-02。

## Context / 背景

控制台会话、API key 与维护主密钥承担不同职责。当前 lookupSession 可以从有效签名 JWT 建立身份，但签名不能说明用户仍有效、会话未撤销或权限没有变化。models/access 与 limits 的部分依赖错误未传播，使“读取失败”和“没有限制”混淆。

可观察信息是服务端会话、用户状态、成员关系、策略版本和目标资源；可控制动作是是否允许新上游工作。必须保证依赖故障不会扩大权限，且同一身份在模型列表和调用入口的作用域一致。

## Decision / 决策

1. 本地登录和 SSO 统一生成 Principal；JWT 仍需校验服务端 jti/会话记录、过期、撤销和当前权限版本。明文令牌不进入业务日志。
2. AuthorizationService 按 action、resource、已验证 scope 求值，返回决策和独立依赖错误。角色是能力模板，管理模型不自动授予推理能力。
3. 模型策略逐层取交集，显式拒绝优先。inherit、allow_list、deny_all 明确区分，空 allow_list 表示没有授权。多团队用户选择一个合法调用上下文，不能拼接不同团队的模型、预算和凭据。
4. 会话/权限/必要凭据读失败返回服务不可用；对象不存在、撤销或明确拒绝返回相应拒绝。禁止用主密钥替代普通会话修复列表错误。
5. 需要立即撤销的入口读取权威版本或已证明一致的撤销索引。TTL 缓存只能承诺明确的撤销延迟。
6. 新工作在持久化 attempt/task 准入事务提交处确定授权快照。之后撤销阻止新工作，但不删除已发生工作及其结算事实。查询与下载继续检查当前权限。

## Consequences / 影响

模型列表、推理、任务、报表共用一个决策服务，避免各 handler 自行解释空名单。数据库故障时新工作可能全部被拒绝；维护成本换取故障不放权。已有无数据库开发模式必须显式标记并限制为本地测试。

最坏情况下无法取得撤销状态。此时“仍有效”和“刚撤销”对网关不可区分，继续允许任何一个都不能保证立即撤销。选择拒绝是满足安全保证的必要代价；不承诺追回已经发送到供应商的任务。

## Rejected alternatives / 否决方案

- 仅验证 JWT 签名：无法落实即时撤销与成员权限变化。
- 所有管理员默认可推理：将管理权限扩张成费用权限。
- 数据库异常时沿用不限额身份：故障扩大授权。
- 合并所有团队模型并任取预算：缺少同一作用域的授权证明。
