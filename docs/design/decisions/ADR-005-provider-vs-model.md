# ADR-005 供应商、模型和部署的领域类型

状态：Proposed（待实施）。日期：2026-10-02。

## Context / 背景

模型选择器出现 qiniu、fennoai，是配置来源和模型条目混用的表现。同一供应商提供多个模型，一个模型别名也可以有多个部署。供应商凭据本身不是可执行模型；名称黑名单无法长期保证正确分类。

## Decision / 决策

明确四种实体：Provider 定义供应商与认证配置；Credential 定义受控凭据和可用作用域；ModelAlias 定义用户可选的逻辑模型与发布策略；Deployment 连接 alias、provider、upstream_model、adapter、配置和凭据。价格目录是独立参考数据，关联需明确来源和版本。

模型是否可选由类型与有效部署证明，不能仅从字符串推断。qiniu/fennoai 的供应商记录不进入模型下拉；供应商下的真实 upstream_model 可以映射为已授权别名。用户只获得公开模型展示字段。

迁移旧混合记录时用结构、配置和引用关系分类，歧义项隔离到管理员诊断，不猜测成可调用模型。兼容读路径保留显式 kind，新增写入验证实体类型、引用存在性与租户关系。

## Consequences / 影响

管理员配置需要区分供应商凭据和模型部署，前端选择器更清楚。已有混合条目可能需要人工确认；目录条目没有部署时仍可介绍，但不能进入我的模型。适配器与模型映射可以独立扩展，不必修改所有用户页面。

最坏情况是旧记录只有一个名称，没有结构或部署证据。模型与供应商两种解释均与观察兼容，因此没有可靠自动分类策略；隔离歧义是保证不会误发布的必要代价。

## Rejected alternatives / 否决方案

- 硬编码排除两个名称：新的供应商记录仍会混入，合法同名别名也可能被误删。
- 每个供应商默认映射一个聊天模型：未证明 upstream_model 与 adapter。
- 成本表全部导入 ModelAlias 并默认发布：把价格覆盖当成路由能力。
