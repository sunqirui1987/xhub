# 13 测试与验收计划

> **目标设计，不是当前行为。** 本文描述的是计划要实现的架构。现在实际运行的行为见 [docs/current/](../current/)。两份冲突时，以 `current/` 和代码为准。

状态：项目已有 Go 和前端测试，本章定义修复后的新增验收门槛。现有测试通过只能说明现有断言通过，不能证明目标架构已实现；catalog 的 779 条路由也不是生产协议覆盖率。

## 验证层级

| 层级 | 范围 | 必须保存的证据 |
| --- | --- | --- |
| 单元 | 权限代数、金额/舍入、usage 规范、状态转换 | 边界输入与独立预期值 |
| 契约 | 每个 adapter/transport/provider 操作 | 已核验文档、真实去敏样本、版本 |
| 集成 | 实际数据库/Redis、唯一约束、事务/outbox | rollback、重放和投影重建结果 |
| 并发/故障 | 多进程、崩溃、租约、响应丢失 | 故障注入点、最终状态及账本对账 |
| 前端 E2E | 登录、我的模型、权限、日志和任务 UI | 普通用户/管理员分别验证 |
| 真实沙箱 | 指定供应商真实调用和收费 | 请求关联 ID、用量、输出和账单对照 |

固定占位响应或同一 OpenAI fixture 不能验证所有协议。外部付费测试在实际接入阶段按已授权账户和限额进行；本次文档验证不运行真实生成。

## 场景矩阵

| 领域 / 缺陷 | 故障与边界 | 必须成立 |
| --- | --- | --- |
| 会话 F02 | 有效签名但撤销/过期/权限版本旧；数据库超时 | 拒绝新的付费请求，不能靠 JWT 签名继续授权 |
| 权限 F01/F03 | membership/实体/凭据读错；Redis 强制限流失败；跨租户 ID | 不放宽作用域，不启动不确定付费工作 |
| 可用模型 F07 | 无部署、停用、失效凭据、不支持操作、健康阻断 | 每个返回项有授权有效部署 witness；无 witness 排除 |
| 入口事实 F04/F08 | 各阶段拒绝/失败；终态落库失败；成功后崩溃 | 已接收请求恢复后唯一终态，失败不伪装零成功 |
| 用量 F08 | SSE UTF-8/JSON 跨 chunk；重复/缺失末帧；单位冲突 | 无重复累加，未知明确，媒体无固定 token |
| 幂等 F05 | 同批/跨批相同键；跨进程竞争；相同键不同 payload | 一份结算；内容冲突报警；业务幂等冲突 409 |
| 预算 F03/F04 | 多主体并发；预占不足；事务步骤失败；跨周期长任务 | 所有主体一起成功或回滚，S+H≤B |
| 缓存 F06 | 100 次命中；权限撤销；旧条目；跨租户摘要相同 | 生成只收费一次，命中无重复生成用量/费用 |
| 报表 F09 | 删 key/改名/转团队/改价；查询错误；夏令时 | 历史不变，错误非空成功，半开区间无重漏 |
| 协议 F10/F12 | 非 POST、multipart、binary、WebSocket、断流 | 实际传输闭环，占位能力不发布 |
| 扩展 F11 | 超时、拒绝、拓宽权限、收费建议、重复通知 | 策略明确、核心不变量独立、外部副作用去重 |
| 异步 F13 | 提交丢响应；回调/轮询竞争；取消竞态；输出过期 | unknown 不重发/不释放风险；终态与结算唯一 |

权限依赖读错需要故障注入返回真实 error，不能只测试“空列表”。可用列表 witness 可在测试中检查选中的 deployment/version/adapter，并以相同策略验证准入；列表之后撤销配置时，调用必须重新检查，不承诺列表快照永久可调用。

## 崩溃点与并发证明

依次在接收提交前/后、预占提交后、attempt intent 后、上游发送后、external_task_id 落库前、终态 CAS 前、结算事务每一步、事务提交后 outbox 投递前终止进程。启动多个恢复 worker；检查没有“先收费再丢账”或“先释放再发现已执行”。

预算测试使用已知费用上界与独立预期账本，至少包含高并发争抢、不同锁顺序和死锁重试。测试验证具体执行，数学保证来自 [预算不变量](06-billing-and-settlement.md)：准入锁内 S+H+R≤B；结算 C≤R，使增量 C−R≤0。无费用上界时有限预占无法保证硬预算，验收应拒绝操作或明确不同承担策略。

唯一终态/结算由数据库唯一约束和事务证明至多一次；恢复扫描在数据库最终恢复、worker 最终运行条件下提供最终完成。外部服务无幂等/查询时，发送后丢结果无法辨别已执行与未执行，不能同时保证自动重试成功和绝不重复，正确结果是 unknown。并发压力测试不能代替这些前提。

## 发布门槛与证据记录

每个发布能力记录 provider/model/operation/transport、adapter/version、文档版本、测试环境/数据库版本、样本摘要、测试结果、用量/账本对照、故障恢复结果和已知限制。凭据及完整敏感内容不入证据库。

生产门槛：F01–F06 的权限/账务阻断修复通过；发布能力的 F07–F13 相关场景通过；迁移固定水位对账相等；普通用户 E2E 无越权；回滚演练不会启用双重扣款；无未解释金额差异。Seedance 只有真实文档核验、沙箱生成、使用量与费用对照及未知恢复验证后才 verified。

验收结果以通过/失败/未验证记录，未验证不算通过。性能基准需要大数据集数据库分页/聚合及 outbox 恢复演练；实际 SLO 由测量确定。保留未完成项时缩小发布支持矩阵，不能用路由数量或编译成功替代闭环证据。
