# 01 系统模型

状态：当前模块已有基本边界；下述领域对象与服务分工是目标设计，尚未完整实现。

## 领域边界

| 对象 | 定义 | 不能替代什么 |
| --- | --- | --- |
| Principal | 本次请求经过验证的用户或 API key 身份 | 页面角色名称不能替代调用授权 |
| Scope | 当前组织/团队/项目归属，来自可信成员关系 | 客户端传入 team_id 不能授予权限 |
| Capability | 对动作的权限，例如 inference.invoke | 能管理模型不自动等于能消费全部模型 |
| ModelAlias | 对用户公开的模型 ID，附操作与展示信息 | provider 名或 credential 名不是模型 |
| Deployment | 具体上游模型、适配器、凭据引用、路由状态 | 静态价格条目不证明部署存在 |
| Provider | 供应商或转发服务，例如 qiniu/fennoai | 不能单独出现在模型选择列表 |
| ProtocolAdapter | 将规范请求/响应和供应商协议互相转换 | 不拥有身份、授权、账务写入 |
| Usage | 操作的可计量事实，带来源和质量 | 响应文本长度不等于实际 token 或费用 |
| RequestEvent | 本次入口请求的归属、结果及执行快照 | 不代替每个上游 attempt 或异步 task |
| Settlement | 一次可幂等的账本分录集合 | Redis 热计数不是最终账本 |
| AsyncTask | 跨多个入口请求持续运行的媒体工作 | 提交 HTTP 200/202 不代表任务成功 |

## 服务与依赖方向

建议在现有 internal 包边界上增量增加 AuthorizationService、AvailabilityService、RequestRecorder、UsageNormalizer、BillingService、TaskService 和 AdapterRegistry，避免一次重写全部路由。

入口解析 → 身份验证 → 可信作用域选择 → 能力/模型授权 → 部署解析 → 限流与预算预占 → 适配器/传输 → 用量归一化 → 结算/请求终态 → 报表投影。

控制面负责目录、部署、凭据、价格版本和权限；数据面调用已版本化的控制面快照。数据库保存可恢复的请求和账本，Redis 可用于缓存/调度/投影。不能让 Redis 暂时丢数据后通过 HotSpend=0 改变预算真值。

## 权威数据

身份状态与成员关系属于授权服务；模型发布状态属于模型目录；部署协议能力属于适配器注册信息；用量来自上游证据或明确估算；金额来自该次接受工作的价格快照；预算可用余额来自持久化预占与账本。

所有快照带 config_version、permission_version、price_version 和 schema_version。管理更新完成后发布新版本并使缓存失效。请求开始时获取的授权不构成无限期授权：上游启动前进行必要的版本校验，异步提交后的查询与下载仍重新授权。

## 故障与保证

跨数据库与外部供应商无法提供天然的全局事务。保证本地原子性与可恢复状态，外部副作用通过幂等键、对账和人工核查处理。上游不支持幂等且提交结果丢失时，只能记录 unknown，不得保证“恰好生成一次”。

预算与授权失去权威读取能力时停止新工作；已经运行的任务继续恢复与对账，不因权限缓存故障丢失账单。可用模型查询不能预知查询后发生的供应商停机，只保证生成快照时满足本地资格条件。

## 验收

任一 provider 接入只增加适配器及配置，不能复制认证和扣费链路。所有推理操作共享同一权限决策、请求 ID 和账本；媒体服务复用这些边界。占位接口必须返回显式 unsupported，不能写入成功指标。
