# 供应商目录与模型能力

供应商连接的 `credential_info.catalog_id` 对应编译时注册的专用能力目录，例如 `qiniu` 对应 `internal/provider/qiniu`。连接名称、认证协议和目录 ID 分别保存；目录 ID 是注册表键，不读取用户输入的文件系统路径。未注册的中转商目录（例如 `fennoai`）保留为连接元数据，不阻止通用协议执行或模型发现。

OpenAI 兼容连接使用保存的地址和密钥读取供应商完整 `/models` 列表，包括没有登记专用执行能力的上架模型，再合并本地专用型号，按 ID 去重排序。不会用能力白名单截断供应商列表，联想选择器也不截断搜索结果。首次地址返回 404 或无效的成功正文时，最多尝试一次增减 `/v1`；鉴权错误、限流、服务器错误及网络失败不会通过更换地址重试。

获取失败时，接口保留已登记专用型号并返回真实错误，页面显示降级原因，仍可选择本地型号或手动输入。没有专用型号时展示错误并允许手动输入。已注册的官方专用连接（例如 `volcengine`）使用本地登记型号，不强制访问 OpenAI `/models`。价格目录与上游模型列表相互独立。

模型编辑器从 `/public/endpoints` 读取已实现的协议，普通型号按连接默认选择 OpenAI、Vertex、Gemini 或 Anthropic。选择菜单展示所有与连接兼容的已实现协议；用户可以切换。未登记型号也可使用通用协议，不需要为每一个供应商或上架型号新增执行白名单。

FAL、Ark 和 Bypass 使用实际登记的执行器和操作路径。专用协议也允许选择；选择后型号或目录不匹配时，页面解释原因，保存接口和数据面校验固定路径与连接能力。七牛的 `bytedance/doubao-seedance-2-0-260128` 使用 `qiniu_contents_generation` 和 Ark Bearer 鉴权；`bytedance/seedance-2.0/text-to-video` 使用 `qiniu_fal_doubao_20`，`byteplus/seedance-2.0/text-to-video` 使用 `qiniu_fal_dreamina_20`，通过 FAL 队列和 Key 鉴权执行。普通 OpenAI 兼容连接可承载这些执行器；最终鉴权由执行器按上游协议转换。

新增专用能力时，在供应商包登记 `Transport` 的 `CatalogID`、认证连接白名单、操作路径和参数规则，再通过 `RegisterModel` 登记上游型号与 `TransportID`。供应商包必须进入编译时加载列表；目录名或价格条目不会产生执行器。

保存模型时，后台从已保存连接读取目录，覆盖请求中伪造的 `model_info.catalog_id`。通用执行只校验连接类型、协议和端点；专用执行额外校验目录和型号。数据面每次重新读取连接目录，阻止使用不属于当前目录的专用能力。目录元数据不会传入上游参数。

对外模型名称支持 `/`、`:` 和 `：`，上游 ID 保持独立。名称中的空路径段、`.`、`..` 被拒绝，避免路径歧义；带路径的名称可用于 Gemini 模型操作和已登记 Bypass 路由。

验证使用完整本地模型目录、Ark/FAL 测试服务、真实隔离 PostgreSQL、网关及浏览器，不使用真实供应商密钥，不验证收费任务和外部服务的在线可用性。
