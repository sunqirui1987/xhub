# 运行行为与限制

## 完整响应缓存

`internal/cache` 是每个进程独立的 8192 项 LRU，只存响应字节，读写均复制。没有 TTL，容量淘汰和显式 `Flush` 只影响当前进程；重启丢失内容，没有跨实例失效保证。

普通数据面仅在非流式路径读完整响应缓存。缓存键包含调用方、operation、公开模型、正文，以及模型配置、有效路由设置、会话和查询串的摘要。模型价格、暂停状态和路由配置变化会改变键。Chat/Responses 在护栏后重新序列化，其他操作不保证正文规范化。具体选中部署、命名凭据及适配器版本没有独立缓存字段。

只有完整成功响应才能写入缓存。命中保留原响应 usage，但本次 `cache_hit` 为真、新增生成费为零。缓存只保存正文，不保存完整上游响应头、状态或生成时间；对结果新鲜度有严格要求时，应评估当前缓存语义。

供应商 prompt cache 是另一种机制：仍发生上游调用，按返回的缓存 token 和输出用量计费。会话粘性不保证供应商缓存命中。

## Idempotency-Key

进程内重放只覆盖带请求头的非流式请求；流式与 WebSocket 不进入缓冲重放。重放前重新认证。API key 以稳定 `KeyID` 隔离；会话以 `UserID + SHA-256(session credential)` 隔离，不保存原凭证。身份、HTTP 方法、路径和幂等键组成记录键，查询串和原始正文组成指纹。

同一进程内相同请求的并发副本等待首个执行。键相同但正文或查询串不同返回 409 `idempotency_conflict`。完整响应状态小于 500 时保留 24 小时；5xx、panic、取消或未完成执行释放占位，后续可重试。官方缓冲响应也可记录。

记录不落盘、不跨副本协调。重启或请求落到另一实例可能重新执行。带副作用的任务不能从这个机制推导供应商侧恰好一次执行。

## 协议适配

`llm.Build` 构造 `Upstream{URL, Header, Body}`，不发送 HTTP。普通适配路径使用 POST；GET、multipart、二进制上传、WebSocket 和完整异步生命周期需要专门实现，不能仅凭构造器覆盖。

OpenAI 兼容、Azure、Anthropic、Gemini/Vertex 等使用各自请求形状与认证头。部分专用组只有有限 JSON 构造；Bedrock 当前构造简化认证头，没有完整 SigV4 签名。供应商登记、入口能力与真实协议验证必须分别判断。未知或废弃 provider 返回错误。

命名凭据 hydrate 只复制白名单字段：非空 api_key 替换部署旧值，其它字段补空值。`os.environ/NAME` 在 hydrate 时解析，最终 provider 由 hydrate 后的配置确定。缺失凭据不能继续发送空 Bearer。

响应解码统一公共模型名，映射 Anthropic input/output/cache 字段、Gemini usageMetadata 和 Responses 嵌套终态 usage。字段缺失时可能估算，明确零不被覆盖。新增协议需验证认证、请求字段、错误、usage 单位、缓存关系及流终态。

Qiniu Responses 的 SSE 转换器增量处理 LF/CRLF 帧和不完整网络块，转换文本、推理文本与终态 usage。未知事件、事件 ID、retry、工具调用及非文本增量没有完整保留。没有通用的流式适配状态机和统一 partial/unknown 计量契约。

## 官方媒体任务

内置固定转发路径：

| 供应商 | 创建 | 查询 | 列表 |
| --- | --- | --- | --- |
| Qiniu | `POST /v3/contents/generations/tasks` | `GET /v3/contents/generations/tasks/{id}` | 未登记 |
| Volcengine | `POST /api/v3/contents/generations/tasks` | `GET /api/v3/contents/generations/tasks/{id}` | `GET /api/v3/contents/generations/tasks` |

部署使用登记的 transport；自定义路径文档不参与匹配。成功创建把任务钉到含凭据身份的部署，以调用方、transport 和 task ID 隔离，保留七天。查询使用相同调用范围。Redis 故障时的本地兜底重启丢失。

创建只在明确的 429/5xx 时尝试其它候选。发送或读取结果不明时返回 502，不能盲目创建第二个任务。创建、处理中、失败及列表不推断生成费用；成功终态用量走[结算去重](pricing.md)。

官方转发不执行普通文本护栏或完整响应缓存。当前没有通用取消、回调、下载和任务恢复闭环。部分资源入口只支持元数据操作，其余返回 501；不能把目录中的路由数量理解为全部操作可用。

资源分类同时识别带版本和不带版本的 `/assistants`、`/threads`、`/fine_tuning`、`/containers`、`/videos` 和 `/vector_stores` 路径，两种写法都进入数据面鉴权流程。资源处理器按调用方隔离存储，不能通过省略版本前缀绕过权限。当前只实现 assistants 和 threads 的部分元数据操作，未实现的嵌套线程消息等入口返回 501，而不是伪造成功响应。

## 护栏与日志

Chat/Responses 的支持文本字段可做词表阻断或打码，正文修改进入上游请求、缓存键和交换日志；护栏存储读取失败时阻断请求。它不是多模态分类器，不覆盖所有工具参数或官方转发。

`store_prompts_in_spend_logs` 控制可选正文记录。授权范围见[权限规则](permissions.md)。不要假设正文存储具备自动加密和留存清理；需要内容记录的部署应明确访问权限与保留方式。运行日志避免输出 API key、认证头和敏感正文。

## 运维需要知道的边界

| 行为 | 当前边界 | 运维关注点 |
| --- | --- | --- |
| 预算 | 检查已记录与热支出，没有预占 | 控制并发和上游额度，不能承诺绝不超支 |
| 费用持久化 | PostgreSQL 事务去重，Redis 可排队 | 监控刷写失败、队列增长及供应商账单差异 |
| 速率限制 | Redis 分钟桶或进程内窗口 | 无 Redis 时多个实例不能共享限额状态 |
| 幂等 | 进程内、非流式、24 小时 | 重启与跨实例仍可能重新执行 |
| 缓存 | 无 TTL、无跨实例失效 | 评估结果新鲜度，区别于供应商缓存 |
| 会话与任务钉 | 一小时 / 七天，本地兜底可能丢失 | 重启和过期后不能保证原部署查询 |
| 报表 | 使用记录的用量与价格，缺失字段可能估算 | 与供应商账单核对，不当作完整会计账本 |

这些边界应随实现变化更新。新增保证需要相应的故障与并发验证，不能仅以模拟上游测试或登记能力作证。
