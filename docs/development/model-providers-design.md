# 模型提供商完整重构设计

状态：剩余架构设计提案；动态供应商表单已实现，见 [认证表单](provider-credential-forms.md)。下述旧问题描述保留为设计背景。尚未实现本文的新资源、OAuth 或 Fal AI 官方适配器。已有 `/models` 与 `/v1/models` 的 404 自动回退独立生效于当前模型发现代码。

## 目标与完整范围

用户管理的主资源是“模型提供商”：一个可以复用的上游连接。凭据是连接内部的认证材料。完整重构包含提供商目录、创建与编辑、认证、连接验证、模型发现、部署引用、运行时解析、权限、日志和历史数据迁移；只替换标题或保留两套互相矛盾的配置不满足目标。

完整重构不等于已经实现 LiteLLM 文档中的所有提供商。目录必须逐项说明 XHub 的实际支持情况；存在价格、Logo 或文档不代表可以调用。未注册完整执行适配器的提供商可以展示说明，但不能作为已支持的连接保存和部署。

## 资源与职责

| 资源 | 职责 | 示例 |
| --- | --- | --- |
| ProviderDefinition | 后端登记的提供商类型：认证字段、默认地址、发现策略、执行适配器、端点能力、文档与支持状态 | `openai`、`openai_compatible`、`fal_ai`、`chatgpt` |
| ProviderAuth | 某一连接的密钥或 OAuth 令牌；仅服务端读取，支持替换、撤销与刷新 | API Key、access/refresh token、account_id |
| ModelDeployment | 上游模型 ID、连接 ID、已验证端点/传输、对外别名和价格关联 | 公司中转 → `gpt-4o-mini` → 对外 `chat-default` |
| ModelPrice | 计价来源、费率、单位和版本 | 目录价或手动声明价 |

提供商类型、模型发行方、请求协议分别保存。通过公司中转调用某个 OpenAI 模型时，发行方可以是 OpenAI，连接类型是 OpenAI 兼容，连接实例是公司中转。模型 ID 使用独立字段，不靠首个斜杠推断连接类型；`fal-ai/flux-pro/v1.1` 中的斜杠必须保留。

```text
ProviderDefinition ──定义──> ProviderConnection ──引用──> ProviderAuth
                                   ↑
                            ModelDeployment ──关联──> ModelPrice
```

## 页面与创建流程

页面名称、入口、弹窗和成功失败提示统一用“模型提供商”。名称输入叫“提供商名称”，类型选择叫“提供商类型”；API Key、OAuth 等属于“认证配置”。列表展示名称、类型、地址、认证状态、目录状态、已关联部署数量、启用状态。

创建采用三个步骤，复杂配置以完整页面或宽弹窗呈现：

1. **选择提供商类型**：可搜索并按官方服务、OpenAI 兼容/中转、云平台、媒体服务、订阅账户分组。每项显示可调用能力、认证方式和真实支持状态。未支持项可打开文档，但不能进入可保存状态。
2. **配置连接与认证**：用户命名实例；按定义呈现字段及正确默认值。切换类型保留名称，清除原类型的地址、秘密草稿和目录选项。API Key 不写入浏览器持久存储；已存密钥只显示“已设置”，不回填伪密钥。
3. **验证与保存**：独立呈现认证验证、模型目录和具体模型调用三种结果。允许保存配置合法、目录暂时不可用的连接，但状态标记“未验证/目录不可用”；OAuth 类型尚未完成授权时只能保存草稿，不能启用。保存成功后提供“添加模型”。

一般提供商的验证使用无计费接口。没有这样的接口时明确显示“无法进行无计费验证”；禁止用创建图片或视频任务充当自动测试。用户在模型详情主动发起调用测试时，才选择请求内容并说明可能发生的实际费用。

提供商详情分为“连接配置、认证、模型目录、关联模型”。密钥轮换和 OAuth 重新授权留在认证页；模型部署表单只选择连接并配置模型、能力和价格。提交失败保留草稿；异步保存成功以后才关闭弹窗。

## 提供商类型示例

| 类型 | 认证与默认地址 | 模型目录 | 执行方式 |
| --- | --- | --- | --- |
| OpenAI 官方 | Bearer API Key；`https://api.openai.com/v1` | 官方目录适配器 | OpenAI 已登记端点 |
| OpenAI 兼容/中转 | Bearer API Key；用户地址，认证要求由类型定义 | 自动、无 v1、含 v1、自定义相对路径 | 只开放 XHub 能执行的兼容端点 |
| Fal AI 官方 | `Authorization: Key ...`；`https://fal.run` | 适配器内置支持模型 + 手动 ID；没有已验证目录 API 时不探测 `/models` | 按具体模型的图片协议转换；队列/视频需另外登记 |
| ChatGPT 订阅 | OAuth 设备码；`https://chatgpt.com/backend-api/codex` | 适配器支持列表；账户可用性另行验证 | 原生 Responses；受支持模型可声明 Chat 桥接 |
| Anthropic、Gemini、Azure、Bedrock 等 | 各自字段、版本、区域、角色或工作负载认证 | 各自适配器策略 | 逐项登记与验证，不能继承 OpenAI 目录策略 |


## 模型发现与 v1 规则

目录策略属于连接，调用协议属于执行适配器；改变目录路径不能改变推理地址。

OpenAI 兼容类型提供四项选择：

- **自动（默认）**：按填写地址和类型默认值生成首选目录；只在 404 时尝试一个 `/v1` 变体。整个操作最多两次请求、共享超时、可取消。
- **无 v1**：规范化输入中目录用的末尾 `/v1` 后请求 `/models`，只执行一次。
- **含 v1**：规范化目录末尾版本段后请求 `/v1/models`，只执行一次，避免 `/v1/v1/models`。
- **自定义**：填写同一连接根地址之下的相对目录路径，不接受另一个主机的完整 URL；保留必要的代理前缀。

例如连接地址 `https://relay.example/proxy`，自动依次尝试 `/proxy/models` 和 `/proxy/v1/models`；填写 `https://relay.example/proxy/v1` 时顺序相反。只有目录路径上的最后一个 `/v1` 可切换，不能删除中间代理前缀。明确填写完整 `/models` 目录地址的旧数据可迁移为自定义目录，不能当作推理根地址。

401/403、429、5xx、网络故障、重定向及无效返回不执行 v1 回退。授权头由提供商认证适配器决定，不给所有提供商同时发送 Bearer 与 x-api-key。错误返回只包含脱敏路径、状态、操作和原因；两条路径 404 时显示实际尝试路径并保留手动输入入口。

缓存按连接 ID、配置版本和认证版本隔离；同源两个账户不能共享私有模型列表。空目录是成功但为空，内置支持列表不表示账户已经授权，目录成功也不表示每个模型有调用权限。修改地址或轮换认证使旧目录/验证结果失效。

## 后台契约与运行时

以下是拟新增的契约，当前路由尚未提供：

| 接口 | 职责 |
| --- | --- |
| `GET /provider-definitions` | 后端单一提供商定义目录；不包含秘密 |
| `GET/POST /provider-connections` | 查询或新建连接 |
| `GET/PATCH/DELETE /provider-connections/{id}` | 详情、更新与受保护删除 |
| `POST /provider-connections/{id}/validate` | 无计费验证，返回分项状态 |
| `GET /provider-connections/{id}/models` | 只读模型发现，返回来源、可用状态及实际尝试路径 |
| `PUT /provider-connections/{id}/auth` | 替换认证材料，返回状态和新版本，不回显秘密 |
| `POST /provider-connections/{id}/oauth/device` | 创建可取消的设备授权会话 |
| `GET/DELETE /provider-connections/{id}/oauth/sessions/{session_id}` | 查询或取消；会话绑定当前操作者与连接 |

ProviderDefinition 必须从可执行适配器登记信息产生，包括 `id`、`display_name`、`support_status`、`auth_methods`、字段 Schema、发现策略和 `transport_ids`。复用现有 `internal/provider` 的端点/传输登记，不再让价格目录承担连接字段或协议支持的来源。前端选项、字段和后台验证读取同一版本的定义。

连接 ID 是不可变标识，名称可编辑。更新使用版本条件，冲突返回 409；不存在返回 404，字段/类型错误返回 400，权限不足返回 403，存在关联部署时删除返回 409。上游鉴权、限流与暂时不可用作为分项结果返回，管理接口身份错误与上游错误分开表达。

模型保存必须校验 `provider_connection_id` 和端点传输匹配。运行时先解析连接与认证，再构造不可变调用上下文，地址、认证和提供商协议以连接为唯一来源；部署不能静默覆盖连接地址或借目录路径回退更改推理协议。确需特殊地址时建立独立连接。

停用连接立即排除其部署，但不能修改模型对外别名或扩大已有权限。详情列出受影响部署；删除需要先迁移或删除这些引用。正在执行的调用使用已经解析的配置快照；后续请求读取新配置版本。

## OAuth 与秘密存储

ChatGPT 授权是独立的服务端工作流：未授权 → 等待用户操作 → 已授权；取消、过期和失败是终态。浏览器只得到验证 URL、用户码、有效期和会话状态；访问令牌、刷新令牌和账户标识归属该连接。

后台按服务返回的间隔轮询，处理 `authorization_pending`、`slow_down`、拒绝与过期；避免阻塞普通管理请求。刷新使用连接级并发控制和认证版本比较，多实例不能重复轮换刷新令牌。失效时标记“需要重新授权”，数据面返回确定的认证不可用错误，禁止在请求过程中启动交互登录。

LiteLLM 的本地 `auth.json` 模式可供开发参考，XHub 的多个连接和实例不能共用一个文件。采用数据库认证记录或部署现有秘密存储；明确验证静态加密是否存在，没有时使用独立加密层、密钥版本和轮换机制。日志、导出、审计和管理响应均不得带明文认证。

## 历史数据迁移与兼容

保留外部兼容契约与完整产品重构可以同时成立；兼容入口必须调用新的统一服务，不保留第二套业务实现。

1. 盘点数据库 `credentials`、YAML 命名凭据、内置种子和部署中的 `litellm_credential_name`；生成不含秘密的迁移诊断。
2. 每条历史凭据生成稳定连接 ID，保存名称别名映射，认证转入秘密记录；显示名变化不改变引用。迁移幂等，不合并同名但不同来源的账户。
4. 计算每条部署当前的有效配置。历史部署覆盖了凭据地址/区域/协议的，按有效配置建立独立连接并重新引用；保持原先调用行为，不能简单删除覆盖项。内联认证也按这一方式迁移。
5. 在事务里写连接、认证及部署引用。存在歧义、无效类型或无法解析的环境变量时报告具体资源并阻止这些资源的启用，不猜测秘密或地址。
6. 旧 `/credentials` 等受支持接口由兼容转换器读写新服务；旧名称映射保留。新建和修改部署只写连接 ID，读取旧部署时明确标记来源。配置导出增加新资源，并提供需要时的 LiteLLM 兼容导出。
7. 验证全部引用、真实数据面和重启后持久化，再删除产品前端旧凭证流程、价格目录的连接字段推断和运行时旧 Hydrate 规则。迁移版本和兼容映射作为回滚依据。
