# 模型、端点与供应商扩展


模型名称、公开协议、上游传输、供应商凭据和价格来源是五项独立契约。客户端先选已授权的模型，再从该模型的真实端点绑定中选择调用方式。价格目录负责价格，不能因为某个模型有价格就推断它支持对话或某种视频接口。

## 数据职责

| 对象 | 负责内容 | 代码入口 |
| --- | --- | --- |
| 供应商及命名凭据 | 连接根地址、供应商身份和密钥 | `internal/provider/registry.go`、供应商管理 |
| 公开端点类型 | 统一适配或原生透传、协议和能力分类 | `internal/provider/endpoints.go` |
| 执行传输 | 允许的方法及路径、鉴权、固定模型、任务查询、用量提取 | `internal/provider/type.go`、供应商注册文件 |
| 模型部署 | 对外别名、上游模型、命名凭据、显式上游传输、自动客户接口及可选直通入口 | `internal/provider/validate.go` |
| 计价绑定 | 目录模型或人工费率，按实测用量及准确规格结算 | `internal/catalog` |

`model_info.transport` 必须引用已登记的上游执行方式。标准客户接口由执行能力自动生成，`model_info.endpoint_types` 可省略；填写时逐项严格校验，Bypass/Fal 必须显式启用。缺少 transport 或使用旧端点 ID 会拒绝部署，不迁移旧数据、不从 mode 或型号推断。

一条部署选择一个上游执行方式。OpenAI Chat、Responses、Anthropic Messages、Gemini、Vertex 对话上游均自动支持五种客户协议，包含七条标准公开路径（两种 Google 协议各有普通及流式操作）。媒体按实际执行操作生成客户入口，图片创建与编辑分别登记。同一对外别名可以配置多条部署，后端按方法和公开路径合并，实际请求只进入支持所选端点的部署池。

## 模型先于端点

统一 /responses 和 /v1/responses 支持默认增量会话：第一轮发送输入，后续只发送新输入及上一轮返回的 previous_response_id。省略 store 或传 store:false 都可续接。网关仍向原厂 Responses 发送 store:false，并在现有会话缓存中保留一小时的临时上下文；这不提供原厂响应检索或长期存储功能。

响应归属和临时历史按调用方、公开模型和入口隔离。流式完成事件发布前保存状态；预算和护栏检查恢复后的完整历史。请求级 instructions 不从上一轮继承。未知、过期或修复前未保存历史的响应 ID 需要重新发送完整历史；原部署不可用时返回 409 continuation_unavailable。没有 Redis 时只保存在当前进程，重启或跨实例请求无法恢复；原生 Bypass 的存储和续接语义由供应商决定。

`/public/endpoints` 提供注册目录，用于配置模型。`/model/available` 返回当前身份可用模型的 `endpoints`，用于对话和对比。公开目录不是某个模型的实际能力清单。

添加模型时先选供应商和上游模型，再选择“上游接口协议”；“XHub 对外接口”默认折叠，展开后展示执行能力并可勾选 Bypass。折叠不改变自动开放的标准接口或已勾选的直通入口；普通模型仅显示一句协议提示，FAL 任务路径提示只在选中 FAL 时显示，错误和不可保存原因始终直接展示。Playground 的“客户调用接口”选择该公开模型实际可执行的客户路径。普通模型按连接默认选择 OpenAI、Vertex/Gemini 或 Anthropic，管理员仍可切换；专用 FAL/Ark 执行按实现路径校验，价格不决定协议。


编辑已保存模型时，端点目录加载期间和加载失败后保留现有端点与传输声明；加载失败会显示错误提示。目录返回后才校验声明是否匹配当前模型。普通型号没有已保存声明时按连接选择常规协议；菜单保留所有连接兼容的实现，专用型号不匹配时解释原因，保存时再次校验。

### 供应商模型目录路径

OpenAI 兼容连接仅使用已保存凭据的地址与密钥读取目录。当 /models 返回 404 时尝试 /v1/models，已含 /v1 的根地址反向尝试去除该段。不根据供应商名称、域名或请求中的临时地址切换协议。


401、403、429、5xx、网络错误及无效目录响应直接保留错误；成功空列表不触发回退。两次请求共用 20 秒上限，遵循管理请求取消且不跟随重定向。两个候选都不存在时，错误列出尝试过的路径和 404 状态，仍可手动输入模型 ID。回退仅用于读取目录，不修改凭据 API 根地址、推理路径或密钥，也不跨供应商寻找目录；非 OpenAI 兼容凭据继续显示协议不支持。

### 模型选择与编辑回归

先验证空输入显示完整列表、搜索与末尾型号选择，再验证供应商模型发现及隔离。通过浏览器保存、刷新、重新编辑官方方舟模型，并检查提交的端点与传输。已有 Chat 部署分别注入端点目录延迟与失败，验证原声明不被清空。未知型号另行手动声明端点及人工价格，确认保存后重新读取型号、端点和价格。

```bash
# 模型与端点专项 + 完整确定性后端回归 + JSON/Markdown/HTML 报告。
make e2e-model-endpoints

# 真实控制台、网关及 PostgreSQL；上游目录使用本地确定性 fixture。
bash scripts/e2e.sh model-discovery.spec.ts model-endpoints.spec.ts wizards.spec.ts writes.spec.ts weighted-routing.spec.ts xgo-guardrails.spec.ts

# 网关管理 API 回归，不触发视频生成或真实供应商计费。

# 完整真实供应商入口，使用 config_provider.yaml 及数据库中已保存的凭据。
E2E_CREDENTIAL_SOURCE=database make e2e
```

浏览器交互结果见 `frontend/playwright-report/index.html`，机器可读结果见 `.e2e/current/results.json`。完整入口为每次运行保存 `.e2e/runs/<run>/summary.json`、`report.md`、`report.html` 与日志。筛选的目录和编辑测试不替代真实视频任务生成、轮询与计费验收；真实供应商超时及跳过项应单独保留在报告中。

对话页在模型切换后保留仍有效的实际端点路径，否则选该模型第一个绑定；没有绑定时禁止发送。对比页每张卡片独立保存模型及其文本端点，视频模型不会被补成 Chat Completions。界面可以复用 Responses 或 Messages 的输入组件，但选择值和请求地址始终使用真实路径，标准 Responses 与 Bypass Responses 分别使用已登记的地址。

原生图片和视频使用参数编辑器，图片编辑可以上传 multipart 文件，异步任务提供已登记的状态及结果操作。原生文本界面只发送该协议支持的参数；端点元数据不包含供应商密钥。浏览器显示实测用量，金额由网关计价。

## 公开原生路径

| 端点类型 | 公开路径 |
| --- | --- |
| `bypass:openai-responses` | `POST /bypass/openai/v1/responses` |
| `bypass:anthropic-messages` | `POST /bypass/anthropic/v1/messages` |
| `bypass:openai-images` | `POST /bypass/openai/v1/images/generations` |
| `bypass:openai-image-edit` | `POST /bypass/openai/v1/images/edits` |
| `bypass:ark-video` | 已登记的 Ark 内容生成任务路径 |


透传保留原生 JSON 的未知字段和数字表示，以及 multipart 的文件内容和边界。转发层替换路由模型并重新注入供应商鉴权，清除客户端凭据及逐跳头。禁止跟随重定向；上游返回的任务查询 URL 改写为网关路径，任务结果固定到创建身份、传输和部署。透传不等于允许客户端指定任意上游 URL。

SSE 按原字节转发并观察完整事件。Responses 必须看到 `response.completed`，Messages 必须看到 `message_stop`；EOF、`[DONE]` 或另一协议的终态不能证明原生调用成功。图片部分事件不增加完成图片数。多张流式图片可能具有不同规格，当前单规格账单无法表达时保留用量并标记待核价。

## 扩展官方模型与协议


新增供应商时登记独立连接信息和鉴权，价格也绑定该供应商的目录条目。新增协议时补端点描述、传输白名单及用量提取器；新的原生非文本协议可以先使用参数编辑器。注册路径仅表示网关能够识别和转发，不等同于所有型号都经过付费实测。

扩展必须验证创建路径、模型选路、任务隔离、原生载荷、业务终态、实测用量、价格规格和重复查询唯一结算。创建操作出现网络错误或 5xx 时结果不明确，上游可能已经受理，不能自动切换部署生成第二个付费任务。

## 计费保证与边界

用量提取与计价分层：成功结果提供 token、输出秒数、完成图片数及规格；目录或部署费率据此计价。请求中的目标时长、推理耗时和总 token 不能替代模型规定的实际计量单位。异步任务状态和结果查询使用同一持久结算身份，重复成功查询不会产生多条收费事件。

缺失用量或复杂价格规则不能算出完整金额时，保存实际事实和 `pricing_blocked` 原因，价格快照为 `unpriced`。Vidu Q2 的区间计价、MiniMax 的输入输出组合及免费额度仍需扩展价格契约；不能抽取最低费率或填统一秒价掩盖这些维度。

当前查询触发异步任务结算，尚无后台补查、预算预占、创建时固定价格版本、待核价自动补价，以及供应商成本与客户售价独立账本。这些是完整商业结算需要补充的能力；现有端点抽象允许继续增加，但不能据此声称已经实现。

## 中文代码注释规范

本模块新增或修改的函数、方法及类型使用中文说明。函数注释以函数名开头，至少包含用途、参数及其语义、返回值、错误或副作用、调用入口和对应测试。涉及密钥时解释鉴权来源和过滤规则，不写实际凭据。复杂分支解释成立条件和业务原因，避免只复述语句。

类型注释说明对象的责任边界；容易混淆的字段分别说明。尤其明确“端点类型、传输、模型 ID、价格 ID”的区别，以及“缺失、明确零、未知规格”的差异。SSE 完成、任务归属、禁止重放、用量合并和去重结算应保留分支注释。注释不得描述已删除的自定义协议或不存在的默认行为。

测试函数说明它保护的用户行为或计费保证、输入环境及是否产生付费调用；默认测试只使用本地注册表、目录和假上游。真实付费测试必须由显式环境开关启用，测试及日志不得输出供应商凭据。

## 对话转换与无兼容策略

客户接口保持 OpenAI、Vertex/Gemini、Claude 三个标准协议家族，Bypass/Fal 使用单独登记入口。标准对话通过统一内部消息表达完成请求、响应、工具调用、工具结果、SSE 终态和用量转换，上游地址、正文和鉴权只由部署 transport 决定。Google 标准入口也经过护栏、路由及计费；原生 countTokens 保留在显式 Bypass 操作中。

目前转换覆盖文本、系统指令、函数工具、完整 JSON 工具参数与流式文本。未支持的多模态、Google thoughtSignature/思考内容、部分工具参数、未知扩展字段在访问上游前拒绝，不能静默丢弃。需要原厂扩展时选择对应 Bypass。缺失实测用量会保留待核价状态，不凭空生成 token。

公开对话别名支持斜线、半角和全角冒号；拒绝空路径段、. 和 ..。Google 入口按最后一个操作后缀解析完整模型路径。旧部署不会迁移，需显式重新配置上游；不会自动清空用户数据库。已废弃的全局设置不进入新严格模板，新写入未知字段仍拒绝。模板使用当前严格路由契约，帮助示例同步验证保存和实际调用。

本次专项报告保存在 .e2e/endpoint-redesign/report.md，真实网关回归包括 25 种普通及 25 种流式协议组合、Google 护栏、凭据隔离、原生图片操作和精确账单。浏览器覆盖上游声明、保存回显、客户接口选择、推理、计费及清理，外部服务使用本地确定性协议服务，不产生供应商付费调用。

## 公开模型回退

模型管理在每个公开模型标题旁提供“配置回退”，单部署模型也可以配置。策略独立于部署默认权重和客户路由模板，以公开模型名称作为目标。三类有序列表分别处理通用错误（429、5xx、连接失败、超时或无可用部署）、上下文超限和上游内容策略错误；本地护栏拦截不会触发回退。

普通 4xx 保留原状态与正文，专用错误不借用通用列表。通用错误先耗尽当前模型的部署，专用错误可直接进入对应目标列表。下级回退使用队列顺序：A 配置 B、C，B 配置 D，则先 B、C，再 D。每个请求最多访问 32 个不同公开模型，不重复尝试模型；禁用、冷却和不兼容目标跳过。回退目标使用自己的默认权重与客户模板策略，重新检查调用权限和预算。适配响应保留请求公开模型名，费用按实际成功部署计价。配置回退时不读取响应缓存，避免跳过目标权限复核。

管理接口 `PUT /model/fallback` 仅平台管理员可写入，例如：

```json
{"model_name":"primary","policy":{"fallbacks":["backup"],"context_window_fallbacks":["long-context"],"content_policy_fallbacks":[]}}
```

`GET /model/groups` 返回每组的 `fallback_policy`。保存拒绝未知字段、不存在的目标、重复目标、自引用及跨错误类型的循环。空策略 `{}` 清除配置。删除或重命名最后一个部署时，若仍有源策略或目标引用，返回 409 `fallback_conflict`；先清除策略或引用即可操作，避免多表写入部分成功。

对话适配与原生 Chat、同步 Responses、Messages、Gemini/Vertex 创建支持回退。`disable_fallbacks: true` 在单次请求禁用跨模型回退，开关不会发送给上游。固定原部署的继续请求、已输出字节的流和可能已受理付费任务的异步创建不会跨模型重放；Responses 的 `background: true` 同样受限。异步任务查询仍遵循原有归属。专用错误识别依赖上游 `error` 包络及已支持标记（例如 `context_length_exceeded`、`content_policy_violation`），未识别的 4xx 原样返回。
