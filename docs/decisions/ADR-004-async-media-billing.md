# ADR-004 异步媒体任务与结算边界

状态：Proposed（待实施）。日期：2026-10-02。

## Context / 背景

视频生成可以持续数分钟，提交、查询、回调、取消和下载是不同操作。Seedance 2.0 的目录价格不能证明某个实际供应商协议已接入。提交返回成功后网关仍可能丢失外部 task_id，回调也可能与轮询并发。

必须保证任务归属、恢复可追踪与本地结算唯一，同时准确表达未知外部结果。

## Decision / 决策

任务提交事务创建 execution、task、预占、submission intent 与 outbox。对外只返回网关 task_id，供应商 ID 保存在受控映射内。重复业务幂等键关联同一任务，相同键不同请求摘要为冲突。

worker 通过租约和 version CAS 领取任务；供应商支持幂等时使用固定键。租约过期只允许接管查询/恢复，不自动重新提交不确定任务。响应丢失且不能查明时进入 unknown，保留费用风险。

轮询与已验签回调写入同一状态机；终态 CAS 与稳定结算键去重。cancel_requested 与已确认 cancelled 分开，取消失败或竞态成功仍可能收费。查询/下载有自己的请求日志，不重复产生生成用量。

执行状态与 settlement_state 分开；按真实输出规格和已核验计量结算，未知用量进入 pending。Seedance 接入选定实际 provider、模型/区域和文档版本，完成真实沙箱及恢复证据后才能 verified。

## Consequences / 影响

需要资产权限、TaskService、查询调度、回调验签、恢复 worker 和任务 UI。价格未知或费用无上界的操作不进入硬预算付费开放。输出链接过期只改变资产状态，不撤销已经确认的任务成功。

最坏情形是外部已接受而本地没有返回记录。对于无幂等/查询的供应商，已执行和未执行给网关相同观察；重发可能重复，不重发可能无法完成。无法同时保证自动完成和绝不重复执行，所以保留 unknown 是必要边界。

## Rejected alternatives / 否决方案

- 提交 202 立即记为生成成功并按默认秒数扣款：尚无输出和真实用量。
- 超时/租约到期直接释放预占：外部仍可能完成并收费。
- 取消请求发送成功就记 cancelled：未取得供应商终态。
- 回调与轮询各自更新 spend：竞态导致重复结算。
- 根据模型名猜 Seedance URL 与字段：不能验证供应商实际协议。
