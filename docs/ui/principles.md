# 设计原则

这是给平台管理员和开发者用的**高密度控制台**，不是营销站。默认首页是 Virtual Keys（`/api-keys`），不是营销落地或仪表盘摘要。

1. **信息优先**：一屏能扫完列表关键列；详情用 Tab，不要把所有字段堆成大卡片墙。
2. **操作可预期**：主按钮固定在页头右侧（Create / Save）。行内危险操作用菜单 + 二次确认。
3. **字段名跟 API 走**：表单 `name` 等于契约字段（`key_alias` 不是 `name`）。
4. **明文只出现一次**：`sk-` 虚拟密钥、凭证 secret 只在**创建 / 轮换成功**的 SecretOnce 模态里，关闭即无法再看。列表与详情只留前缀或哈希。不得把这条规则套到登录、开通、连接、设置等非密钥页。
5. **失败可恢复**：校验错误留在表单上可改；网络超时禁止换 payload 重放。
6. **权限在界面也在 API**：隐藏菜单与隐藏写按钮不能代替 403。Admin Viewer / `proxy_admin_viewer` 读与 Admin 同页，但不出现 Create / Save / Delete / Playground 发送。
7. **窄屏可用**：侧栏可折叠；表可横滑；主按钮仍在。
8. **筛选可分享**：列表的搜索、筛选、排序、分页写进 URL query；刷新、后退、拷贝链接不丢状态。
