# 17 验证用的一套数据

这套数据**不是系统默认**。网关启动只做两件事：建表，以及在配置里写了 `admin_email` 且库里还没有这个邮箱时，创建那一个平台管理员。它不会创建组织、团队、项目，也不会创建下面这些账号。

要拿这套数据做权限检查，必须单独执行：

```bash
go run ./cmd/seed -config configs/config.yaml
go run ./cmd/seed -config configs/config.yaml -verify -gateway http://127.0.0.1:4000
```

第二条要在网关已经监听之后再跑。`-verify` 用各账号登录，核对列表范围。它不改网关代码，也不在启动时自动跑。

演示账号的密码都是 `demo-pass-1234`。平台管理员仍是配置里的 `admin@xhub.local`，密码是配置里的初始密码，不是这条命令设的。

| 账号 | 位置 |
| --- | --- |
| org-a-admin@xhub.local | 组织甲的组织管理员，同时是甲一组的普通成员 |
| team-a1-admin@xhub.local | 甲一组的团队管理员 |
| member-a1@xhub.local | 甲一组的普通成员 |
| team-a2-admin@xhub.local | 甲二组的团队管理员 |
| org-b-admin@xhub.local | 组织乙的组织管理员，同时是乙一组的团队管理员 |
| member-b1@xhub.local | 乙一组的普通成员 |
| outsider@xhub.local | 不属于任何团队 |

甲一组有项目「甲一组演示项目」、一把自己的个人密钥和一把服务密钥。乙一组有项目「乙一组演示项目」。用量各记了一笔，方便用量和日志按人分开。

核对时应当看到：

- 平台管理员看见两个组织和三个团队。
- 组织甲管理员看见甲一组和甲二组，看不见乙一组，用户列表里没有乙一组的人和无团队用户。
- 甲一组管理员只看见甲一组，用户列表里有本组的人，没有甲二组管理员。
- 甲一组成员只看见自己所在的组和自己的项目，用户列表里只有自己。
- 无团队用户看不见任何团队，用户列表里只有自己。
