# 14 团队管理

状态：控制台团队页已按当前网关能力收过。本文描述现在能用的行为，不是 LiteLLM 原版控制台。证据：`internal/iam/teams.go`、`internal/gateway/identity/handlers.go`、`internal/gateway/identity/members.go`，以及 `frontend/src/components/Teams.tsx`、`frontend/src/components/team/TeamInfo.tsx`。

## 团队是什么

资源层级是**组织 → 团队 → 项目**。用户只通过团队获得权限。没有组织成员这一层，也没有项目管理员。

一个团队属于一个组织，并且始终至少有一位团队管理员。创建团队的人会成为第一位团队管理员。平台管理员创建团队时必须选择组织，并填写名称。说明、模型列表和预算上限可以留空。

模型列表留空表示不限制：团队可以使用部署里已发布的模型。填写之后，团队以及它下面的项目、密钥都只能使用列出的模型。空列表和「一个模型都不给」不是同一件事；要停掉整个团队，用停用（blocked），不要靠留空模型列表。

## 两种角色

账号角色和团队角色是两套，互不影响。会话里如果还写着 `admin` 或 `user`（旧网关签发的），控制台分别当成平台管理员和普通用户，不会显示成 Unknown Role。新会话写的是 `proxy_admin` 和 `internal_user`，结果一样。

| | 平台管理员 `admin` | 普通账号 `user` |
| --- | --- | --- |
| 团队内可以是 | `team_admin` 或 `member` | `team_admin` 或 `member` |
| 创建、删除团队 | 可以 | 不可以 |
| 改预算上限、模型列表、停用团队 | 可以 | 不可以 |
| 改本团队的名称和说明 | 自己是该团队的 `team_admin` 时可以 | 同左 |
| 添加、改角色、移除成员 | 自己是该团队的 `team_admin` 时可以 | 同左 |

团队管理员不能把别人提成平台管理员，不能删团队，不能改本团队的预算上限和模型列表。保存设置时，如果请求里带了模型或预算，网关会拒绝整次保存，所以控制台只在平台管理员的表单里提交这两个字段。

## 控制台

地址：`/teams`。点进某个团队后地址是 `/teams?team=<团队 ID>`。

团队列表有两个标签：

| 标签 | 内容 |
| --- | --- |
| 你的团队 | 当前账号能看到的团队。平台管理员看到全部。 |
| 可用团队 | 可以把资源放进去的团队，和「你的团队」是同一批。 |

创建团队的按钮在列表页。表单只有：名称、组织、说明、模型、预算上限。

团队详情有四个标签：

| 标签 | 谁能看见 | 内容 |
| --- | --- | --- |
| 概览 | 所有能打开这个团队的人 | 已花费、预算上限、模型、成员数、密钥数、说明 |
| 虚拟密钥 | 同上 | 这个团队下的密钥 |
| 成员 | 能改这个团队的人 | 姓名、邮箱、用户 ID、团队角色。可以添加、改角色、移除 |
| 设置 | 能改这个团队的人 | 名称、说明、模型、预算上限、组织、状态 |

成员表不再显示按人预算、速率、周期花费。网关的成员记录里没有这些数，空列会让人以为限额是 0。

编辑成员只改团队角色。角色在界面上写成「团队管理员」和「团队成员」，提交给网关时分别是 `admin` 和 `user`，网关存成 `team_admin` 和 `member`。

## 成员

添加成员只能选已经存在的账号，按邮箱搜索。搜不到人时，先让平台管理员在「用户」里建账号，再建团队关系。邮箱不存在和账号已停用返回同一个「找不到」，不能拿这个接口枚举全站账号。

移除成员会在同一事务里撤销这个人在该团队下的个人密钥。团队或项目上的服务密钥不动。已经记下来的用量留在原来的团队上，人走了账不走。

一个团队不能没有团队管理员。要移除最后一位，先把另一个成员设成团队管理员。控制台会提示：「团队至少要保留一位团队管理员。请先把其他人设为团队管理员，再移除这一位。」

## 密钥

密钥分两种。

个人密钥属于某个人，绑这个人当时所在的团队或项目，只有本人能看。成员被移出团队时，绑在这个团队上的个人密钥失效。

服务密钥属于团队或项目。团队管理员可以轮换、禁用、删除本团队的服务密钥，但只能把可用模型收窄到团队已经允许的范围里，不能扩大。

## 网关接口

管理接口要管理员会话或团队管理员会话。主密钥不能拿来做这些操作。

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| `POST` | `/team/new` | 创建团队。需要 `organization_id`、`team_alias`。调用者成为第一位 `team_admin`。 |
| `GET` | `/team/list` | 团队数组。 |
| `GET` | `/v2/team/list` | 分页列表，字段是 `teams`、`total`、`page`、`page_size`、`total_pages`。 |
| `GET` | `/team/info?team_id=` | `team_info` 里带 `members_with_roles`，顶层还有一份 `team_memberships`。详情页读 `team_info`。 |
| `POST` | `/team/update` | 团队管理员可改 `team_alias`、`team_description`。平台管理员还可改 `models`、`max_budget`、`blocked`。 |
| `POST` | `/team/delete` | 删除团队。只允许平台管理员。 |
| `GET` | `/user/filter/ui?user_email=` | 添加成员时的账号搜索。返回 `{ users: [...] }`，按邮箱或用户 ID 包含匹配。 |
| `POST` | `/team/member_add` | 按邮箱加入。请求体可以是 `{ team_id, user_email, role }`，也可以是 `{ team_id, member: { user_email, role } }`。 |
| `POST` | `/team/member_update` | 改角色。需要 `team_id` 和 `user_id`。 |
| `POST` | `/team/member_delete` | 移除。`user_id` 或 `user_email` 都可以。最后一位团队管理员会得到 400，报错在 `error.message` 里（不是顶层），正文是 `team must keep at least one team_admin`。 |

`GET /team/info` 里每个成员的公开字段是 `user_id`、`user_email`、`user_alias`、`user_name`、`role`、`user_role`、`status`。`user_alias` 和 `user_name` 是同一个值，`role` 和 `user_role` 也是，留着是为了兼容控制台里两处不同的读法。没有预算、没有个人花费。

## 控制台不再展示的内容

这些是 LiteLLM 控制台留下的区块。当前网关不保存、不执行，页面上已经拿掉：

- 对象权限，以及 MCP、智能体、向量库、搜索工具、技能的授权
- 成员权限，也就是给非管理员开放某几条管理路由
- 「我的用户」标签，以及按人的预算、TPM、RPM、密钥时长
- 默认团队设置（SSO 和默认成员权限）。SSO 兑换会话的接口已经删除
- 护栏、策略、日志回调、路由器、模型别名、密钥管理器、透传路由、访问组
- 软预算、预算重置周期、预估输出 token

创建和保存如果还带上这些字段，网关会忽略。不要把「请求返回 200」理解成这些设置已经生效。

## 常见失败

| 现象 | 原因 |
| --- | --- |
| 添加成员时搜索没有结果 | 账号还没建，或者邮箱打错。搜索是包含匹配，不是新建账号。 |
| 移除时提示至少保留一位团队管理员 | 这个人是最后一位 `team_admin`。先改别人的角色。 |
| 团队管理员保存设置失败 | 请求里带了 `models`、`max_budget` 或 `blocked`。这三项目前只给平台管理员。 |
| 模型列表是空的，但调用被拒绝 | 空列表是不限制。拒绝来自模型没有发布、没有部署，或者密钥自己的范围更窄。看模型文档，不在团队页上加「全部模型」这一项。 |

## 验收

- 平台管理员能创建团队，表单里看不到护栏、日志、路由器、对象权限。
- 详情页只有概览、虚拟密钥、成员、设置，文案是中文。
- 已有用户能按邮箱搜到并加入；加入后出现在成员表。
- 普通成员可以移除；最后一位团队管理员不能移除，提示里写明原因。
- 团队管理员保存时只提交名称和说明；平台管理员还可以提交模型、预算上限和停用。
- `GET /team/info` 的 `team_info.members_with_roles` 与数据库里的 `team_members` 一致。
